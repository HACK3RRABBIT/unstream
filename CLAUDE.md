# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Unstream is a self-hosted music + anime downloader. Paste a Spotify / Deezer / Apple Music / YouTube / SoundCloud URL, or search, and get tagged audio files (or muxed anime episodes) at a chosen quality. No accounts, no API keys — every metadata provider is public and keyless by design. UI ships **Farsi-first**, English as a second locale. Two containers: FastAPI backend (`backend/`) and Vite + React frontend (`frontend/`); nginx serves the built frontend and proxies `/api` to the backend (same origin, no CORS). The live deployment is `compose.dokploy.yml` (GHCR images, rebuilt weekly); the one-command self-host flow is `docker-compose.yml`.

## Commands

Backend (Python 3.12+, [uv](https://docs.astral.sh/uv/)):
- Run the API: `cd backend && uv sync && uv run uvicorn app.main:app --reload --port 8000`
- Full tests: `cd backend && uv run pytest`. One file: `uv run pytest tests/test_anime.py -q`. One test: `uv run pytest tests/test_anime.py::test_nyaa_range_separators_are_batches -q`

Frontend (Node 20+):
- Dev server: `cd frontend && npm install && npm run dev` (Vite at :5173, proxies `/api` → :8000)
- `npm run lint` (oxlint) · `npm run format:check` (prettier) · `npm run build` (runs `tsc -b`, then Vite)

CI runs `uv sync --frozen && uv run pytest -q` for the backend and `npm ci && npm run lint && npm run format:check && npm run build` for the frontend. `UNSTREAM_DEFAULT_LOCALE` (fa|en) is read into a `/config.js` the frontend loads at startup, so it works in dev too: `UNSTREAM_DEFAULT_LOCALE=en npm run dev`.

## Architecture — read these together

Everything downstream sees only the shapes in `app/models.py` (`Track`, `Collection`, `SearchResult`); every metadata provider maps to them. `Track.media` is `"audio"` (music pipeline) or `"video"` (anime episodes), and `Track.source_url` either points at a real YouTube/SoundCloud page or carries a synthetic `anime://<provider>/<animeId>/<season>/<episode>` plan.

Metadata providers (`embed.py` Spotify embed pages, `deezer.py`, `itunes.py`, `soundcloud.py`, `ytdlp.py`) are all keyless; search fans out to several in parallel and dedupes by name + artist. There is deliberately **no Spotify Web API** (requires a Premium subscription since 2025).

**Download pipeline** (`app/downloader.py`): `download_track()` dispatches on `track.media`; for video it lazily imports the anime pipeline (avoids a cycle). For audio: download the track's own URL, or `ytsearch8: "<artists> - <title>"` picking the result whose duration is closest to the catalog's (rejects live versions / hour-long mixes); retries exclude the exact uploads that failed, and the last attempt searches SoundCloud instead of YouTube. `quality` is an mp3 bitrate (`128`/`192`/`320`) or `original` — the latter keeps the upload's own stream, copy-codec remuxed into a pure-audio container (webm→opus, combined mp4→m4a). mutagen tags in whatever format the container speaks; cover art and lyrics are nice-to-have and never fail a download.

**Jobs** (`app/jobs.py`): in-memory only — a restart loses in-flight progress (accepted trade; the files on disk are the durable artifact, and a queue would be a second stateful service). One `TrackState` per track carries status/progress and, for anime, `provider` + `served_quality`. Two thread pools: the shared audio pool (`DOWNLOAD_WORKERS`, default 3) and a smaller video pool (`ANIME_DOWNLOAD_WORKERS`, default 2) because episodes are 100–700 MB each. Cancellation is `threading.Event` set by `cancel()` (which also writes the terminal status so the UI answers instantly); workers poll it between attempts and from inside the yt-dlp progress hook, and `Cancelled` is its own exception so the retry loop never mistakes being called off for a broken upload. A background sweeper evicts finished job dirs by TTL then by `MAX_DOWNLOADS_GB`.

**Anime** (`app/anime/`):
- `providers.py` — `EpisodeSource` / `EpisodeStream`, `ProviderCapability`, `QualityUnavailable`, and the provider registry. Explicit `ANIME_PROVIDER_ORDER` (default `nyaa,anivexa,hianime`) wins verbatim; when unset `order_for(quality)` is **quality-aware**: `anivexa` leads for `<=720p`, `nyaa` leads for `1080`/`original`. `ProviderCapability` (`ok`/`unavailable`/`unknown`/`not_suitable` + verified `qualities`) powers the quality picker; `qualities=None` means "not probed" and must never be read as absent. The plan URL is `anime://<provider>/<animeId>/<season>/<episode>#anilist=<id>&title=<name>` so a fallback provider keyed by title (Nyaa) and one keyed by AniList id (anivexa) can both re-resolve the same season.
- `routes.py` (`/api/anime/*`) — AniList search (`/search`, franchise-grouped TV vs movies; the per-result franchise walks run concurrently), detail (`/{media_id}`, full season chain), download (`/download`, resolves one season to episode `Track`s and hands the batch to `jobs.start` — same ZIP/cancel/sweeper as music), per-season capability (`/{media_id}/season/{season}/sources`, quality picker), verified qualities for many episodes at once (`/{media_id}/season/{season}/qualities?episodes=1,2,3` — capped at `MAX_QUALITY_EPISODES` 50, probed concurrently; the frontend uses this one) with the single-episode `/episode/{episode}/qualities` kept beside it on the same helper, and synopsis translate (`/translate`, keyless Google, SQLite-cached). **The batch endpoint exists because one request per episode was both slow and self-defeating** — the browser ran six at a time and each was charged against the 30/minute `resolve` limit, so a selected season 429'd its own tail into "couldn't check". Download carries `subs: list[str]` (`eng`/`fas`/`none` → `[]`; the UI exposes four presets, default `["eng"]`; legacy single-string accepted).
- `nyaa.py` — self-downloading provider (`streams_hls=False`). Searches nyaa.si by title+episode, classifies rows into singles vs batches (`_episode_ranges` / `_RANGE_RE` / `_BATCH_TAG_RE`), matches requested resolution strictly (`_title_resolution`; raises `QualityUnavailable` when no release claims it), torrents via aria2c or libtorrent, and extracts a single episode out of multi-episode batches. Also exposes `episode_resolutions(src, episode)` for the per-episode quality probe. Its two query forms run concurrently, under a process-wide ceiling of 4 in-flight searches (`_SEARCH_SLOTS`) so batched probes can't turn nyaa.si's interstitial on. aria2 reports live progress by tailing its own summary log (`_aria2_progress`) — a torrent used to sit at 0% until the file appeared. **A multi-episode torrent must never be whole-downloaded as if it were a single episode** — if the episode can't be extracted it fails cleanly so the chain can try the next provider.
- `anivexa.py` — HLS sidecar provider (`streams_hls=True`, `ANIVEXA_URL` env, empty = disabled). Thin facade over `deploy/anivexa` (Node service aggregating ~5 streaming sources: `anikoto`, `anineko`, `anidbapp`, `animedunya`, `animegg`). Per-resolution internal chains (`_INTERNAL_CHAIN`: 480→animedunya first, 720/1080→anineko/anikoto first, original→animegg first), master-playlist pre-checks in rungs (`_master_heights` / `_stream_from`), and a single-flight capability cache (`provider_capability` per season + `episode_capability` per episode, `UNKNOWN` never cached as `unavailable`, `VERIFIED_TTL` 15m / `UNAVAILABLE_TTL` 2m / `UNKNOWN_TTL` 60s, 25s `PROBE_BUDGET`). **Which internals carry an anime is a per-anime fact** (`_carrying_internals` / `_carry_cache`, keyed by AniList id alone), probed concurrently and reused by every season probe, every episode probe and `_download_chain` (verified sources asked first) — re-asking it per episode is what made a season's quality scan take minutes. Its cached "inconclusive" flag travels with the answer: an empty carrying list with that flag is UNKNOWN, never an absence. A dead sidecar is rested `SIDECAR_REST` 60s so chain builds exclude it briefly.
- `hianime.py` — HLS scraper (`streams_hls=True`); yt-dlp with a strict `_format_selector` (exact height, no unrestricted `/best`).
- `quality.py` — **resolution is a rung, not a pixel height** (`rung`, `matches`, `band`, `width_band`). A frame is named by the larger of its own height and the height its width implies at 16:9, snapped to the nearest standard rung within 6%: 1920x804 (letterboxed) and 1440x1080 (4:3) are both *1080*, 1600x900 stays *900* and answers only to 900. Comparing raw heights for equality was rejecting real 1080p releases post-download and hiding servable resolutions in the picker. One source of truth for the ffprobe check, the HLS ladder reader and the yt-dlp format selector.
- `anime/downloader.py` — `download_video_track()` walks the provider chain (a failing provider is skipped; the next is asked at the **same** requested quality — never silently re-served at another height), then verifies the result before success: `_probe_dimensions` (ffprobe width+height, source of truth; falls back to `_probe_height`) and `_check_served_quality` — any explicit resolution (not a closed 480/720/1080 set — `is_video_resolution` accepts any `^\d{3,4}$`, `original` is the only non-numeric choice) whose served **rung** differs from the request (or can't be verified) raises `QualityUnavailable` and the chain continues. `_format_selector` asks for the rung's height band OR its width band (so a widescreen cut is selectable at all) and still has no unrestricted `/best`. HLS fragments are fetched `ANIME_HLS_CONCURRENCY` (8) at a time — serial fragments, not bandwidth, were most of an episode's download time. Up-front capability skip (`_provider_capability` → `unavailable`/`not_suitable` skips without probing; `unknown` never skips), per-provider `_reanchor` so a fallback gets the season title not anivexa's numeric id, and a two-attempt loop with quality-vs-generic error aggregation (any `QualityUnavailable` → clean "requested quality unavailable" rather than a generic failure). `meta` records the real `provider` + `served_quality` (never echoed from the request), which jobs.py surfaces as `TrackState.provider` / `served_quality` in the API.
- `subtitles.py` / `subtitle_source.py` / `subtitle_translate.py` — subtitle pipeline (see below).
- `opensubtitles.py` — optional last-resort English subtitle source (OpenSubtitles, `OPENSUBTITLES_API_KEY` env, empty = inert). Consulted only when the serving provider offered no English track and the user asked for subs; validates parseable SRT/VTT with real cues before muxing. A failure returns `None` — subtitles never fail a download.
- `anilist.py` (metadata) — a franchise walk fetches a whole BFS **level** in one `id_in` request (`get_many`) instead of one request per season, over a shared per-id media cache (`_media_cache`, 10m) so the overlapping walks a search page triggers are paid for once. `translate.py` (keyless Google-Translate of synopses, SQLite-cached, 30-day TTL).

Subtitles (`app/anime/subtitles.py` + `subtitle_source.py` + `subtitle_translate.py`): providers hand back subs in two shapes — Nyaa embeds soft tracks inside the mkv, HLS sources attach an external VTT URL. `subtitles.py` normalizes either into SRT `Cue`s (timestamps preserved verbatim) and muxes 0..N `mov_text` tracks into the final mp4 (`mux_subtitles`, `-c copy`). `subtitle_source.py` preserves `extract_embedded` (ffprobe per-type subtitle indices, `font-fa`-style cue normalization) then `translate_eng` derives Persian by translating cue dialogue only. `subtitle_translate.py` translates that English SRT via the keyless Google mechanism (`translate.py`), cached in SQLite keyed by `sha256(normalized English SRT) + target language`, never failing the download. **Cues are deduped, batched and translated concurrently** (`_chunk` / `_translate_chunk`, `SUBTITLE_TRANSLATE_WORKERS` 6) — one request per cue, in series, took longer than downloading the episode. A batch whose answer comes back with the wrong number of lines can't be aligned to cues, so it falls back to one call per cue for that batch alone: the timeline never slips. The downloader's `_finalize_subtitles` / `_fetch_subs` orchestrate: English-only keeps the single-track path; a Persian request translates and muxes `eng`+`fas` as requested.

Quality is two unrelated concepts: audio **bitrate** and video **resolution**. `DEFAULT_QUALITY` / `DEFAULT_VIDEO_QUALITY` (`original`) handle them separately. **Video quality is dynamic** — `is_video_resolution` accepts any `^\d{3,4}$` (240/360/480/540/720/1080/1440/2160…) and each provider verifies against what its source actually serves (master ladder, torrent-title parse, ffprobe), all of them comparing rungs via `quality.py` rather than raw heights; `original` keeps the provider's own best stream untouched.

Lyrics (`app/lyrics.py`): LRCLIB → Genius → lyrics.ovh, with circuit breakers that rest a refusing source and an outage cache (a hit or a miss is served from cache; a cached outage is bypassed by `refresh=1`). **`None` means "sources answered, none has it"; `LyricsUnavailable` means "couldn't ask" — never collapse the two** (collapsing them hid the Genius outage from the metrics for months). Analytics (`app/analytics.py`) is server-side SQLite, off unless `ADMIN_TOKEN` is set.

**Frontend** (`frontend/src/`): single-page, no router — `App.tsx` holds a `View` stack (`useState<View[]>`) for back/forward navigation and a `tab` for music vs anime, both purely client-side. `lib/api.ts` is the one file that knows the `/api` response shapes; it also exports the type guards (`isQuality`, `isVideoQuality`, `isSubtitleLanguage(s)`) everything else uses to validate state coming back out of `localStorage`. `lib/downloads.tsx` (`DownloadsProvider`) tracks jobs outside any view and mirrors them to `localStorage`, so navigating away or reloading never loses an in-flight download — `DownloadsDock` renders whatever it holds. `lib/i18n.tsx` is the whole locale system: `LOCALES` is the only place a language is registered (a dictionary file in `lib/locales/` plus one entry there), `Messages` makes a half-translated dictionary a compile error rather than a runtime blank, and helpers like `useStartAlign` and the Persian-digit matcher handle RTL layout and mixed-script content that `dir`/`lang` alone can't. `CONTEXT.md` at the repo root is the canonical Farsi glossary — the term each domain concept (track, download, quality, subtitle…) must render as in `locales/fa.ts` — check it before touching UI copy. `admin/` is a separate, lazily-loaded bundle mounted at `/admin` by a path check in `main.tsx` (not the router); it's deliberately English/LTR — the one page only the self-hoster sees, not the product — and gated by `ADMIN_TOKEN`.

## Load-bearing decisions (details in `docs/DESIGN.md`, `README.md`)

- **Keyless-only is the constraint that drives provider choice.** That's why the app reads Spotify embed pages instead of the API, and why the lyrics/translate layers are the fragile, rot-prone ones.
- **Sources rot and are IP-dependent:** Genius 403s right now (kept — it's the only Persian-script lyric source, and the block looks per-address, which is fine for self-hosters), AniList 403s these dev boxes, HiAnime is unreachable from datacenter IPs, and YouTube answers `LOGIN_REQUIRED` from a VPS (home egress required). Nyaa + the anivexa sidecar both work from a VPS; Nyaa is the permanent archive, the sidecar is the streaming library — which leads is quality-aware (see `order_for` above). A source that starts refusing is rested, not removed.
- Don't add a Spotify Web API integration, and don't rebuild a transliterator for LRCLIB — both were tried and rejected (design notes explain why).
- **Jobs live in memory by design.** Don't add a queue or database for them.

## Testing

The entire backend suite is hermetic — no network. The pattern (see `tests/test_anime.py`): stub the HTTP boundary (`anilist.franchise`, `anilist._gql`, `nyaa._client.get`), stub the provider registry via `providers()`, and feed canned Nyaa HTML as fixtures. When a test drives the video pipeline with a fake file, stub `_probe_height` too — the real ffprobe returns `None` on non-video bytes, which fails the explicit-quality check. Tests use `monkeypatch` and in-process fixtures only.
